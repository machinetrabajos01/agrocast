Detecting data drift and degradation

  • Data drift: the artifact stores the mean and standard deviation of the training monthly log changes. Each month the last 12 changes are compared with that reference (z-score of the mean and volatility ratio).
  • Performance degradation: every stored forecast is matched with the actual value when the analyst registers the new UPRA month. Two consecutive one-step errors above {{ mon.rules.ape_limit_pct if mon else 5 }}% open a performance incident.
  • Concept drift: the quarterly backtest checks whether the selected model still beats persistence; if it does not, persistence becomes the reference until a new version is evaluated.
  • Upstream changes: a change of the UPRA basket or methodology is checked with the robust z-score of the month of the change (as in January and September 2024).

Retraining criteria and update procedure

Retrain when: a drift alert; two consecutive warnings; a performance incident; a UPRA methodology change; or every quarter with the new months.

  1. python -m src.pipeline --actualizar-fuentes — download sources, prepare data, re-run the comparison.
  2. Check that the selected model still beats persistence in validation; review the independent test.
  3. python -m src.evidence and python -m src.train_model --version X.Y.Z (MINOR for new data, MAJOR for a new algorithm).
  4. python -m pytest; commit the artifact and its model card; deploy.
  5. flask --app app seed registers the version as inactive; the administrator activates it. Rollback = activate the previous version.

Example: on 2026-11-16 the sources were refreshed (TRM to {{ quality.exogenas_ultima_fecha.trm }}, Pink Sheet to {{ quality.exogenas_ultima_fecha.urea_usd }}, SIPSA-I to {{ quality.sipsa_ultima_fecha }}; UPRA index still {{ quality.hasta }}) and version 1.1.0 was packaged and activated.
