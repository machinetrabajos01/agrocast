Public documentation

Technical documentation

Everything required to explain, reproduce and defend the project is organized in the repository.

Repository layers

data/raw/ source files data/processed/ clean modeling tables src/ ingestion, preparation, models, evaluation reports/ metrics, backtests and figures agrosys/ information system: data model, security, processes models/ versioned SARIMA artifacts and model cards supabase/ database migrations (schema agrocast) web/ Flask presentation layer docs/ technical and user manuals, training guide, support, monitoring and maintenance

Reproduce

python -m pytest python -m src.pipeline --actualizar-fuentes python -m src.evidence python -m src.train_model --version 1.1.0 python -m src.food_prices build flask --app app seed flask --app app run

For a fresh data run, the original ingestion pipeline also supports the --actualizar-fuentes option.

Documents

Readable in the browser: user manual, training guide, incidents and feedback, technical manual, monitoring and maintenance, data dictionary. Source code: GitHub repository.

Academic interpretation

The project should be presented as an evidence-based forecasting prototype. The final test block is not used to tune the models, and uncertainty is communicated explicitly.
